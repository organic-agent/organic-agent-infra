전체 구성

색은 흐름의 종류다. 실선은 런타임 트래픽, 점선은 설정·배포·state처럼 요청이 없을 때 흐르는 것. 원 숫자는 각 경로 안의 순서다.

요청·데이터 경로

공개 API

  • api.easyselect.kr → ALB(:80→:443, ACM) → wes-app :8080(ALB SG만) → RDS :5432(EC2 SG).
  • ALB 리스너 규칙이 /internal/admin*을 404로 고정해 공개 경로에서 관리자 API가 노출되지 않는다.
  • 사진 바이트는 앱을 거치지 않는다. 앱이 서명 URL을 발급하고 브라우저가 S3에 직접 PUT/GET 한다. 버킷 CORS는 공개 오리진(SSM cors.allowed-origins)에 admin 오리진을 합친 한 목록을 쓴다.
  • 앱 롤은 Bedrock InvokeModel(추천)·Lambda 셋 invoke·GPU 워커 Start/Stop(태그 Name=wes-score-gpu만)을 가진다.

관리자 (BackOffice)

  • admin.easyselect.kr → Route 53이 Tailscale IP를 가리킨다. tailnet grant는 member + tagged 노드에 tag:wes-admin tcp:443만.
  • wes-admin(t4g.small) 안: Tailscale Serve :443 → Caddy :8443(Let's Encrypt, Route 53 DNS-01) → BackOffice BFF → wes-admin-api :8081. SG 인바운드 0, 두 Docker 네트워크로 격리.
  • admin-api는 전용 DB 계정(Flyway OFF, ddl validate)으로 RDS에 붙고, trace를 같은 Loki로 보낸다. Grafana/Loki 조회 URL은 /wes/admin-api/prod/*에만 있다.

모니터링

  • wes-monitoring(t4g.micro + EIP)에 Loki 3.5.3·Grafana 12.1.1·Caddy를 compose로 띄운다. ALB 뒤가 아니라 monitoring.easyselect.kr → EIP 직결.
  • 앱·관리자 API는 사설 IP :3100으로 push 한다(SG 참조 규칙은 VPC 내부 경로에서만 매칭). 보존 168h.
  • Grafana 비밀번호는 /wes/monitoring/*에 분리한다. 앱이 /wes/prod/를 통째로 읽기 때문이다.

테스트 프론트

  • wes-frontend-test(t4g.small + EIP, Ubuntu arm64) → test.easyselect.kr, Caddy가 정적 파일을 서빙. 관리자 API로 가는 경로·권한은 없다.
  • 배포는 test-web 저장소의 OIDC 롤이 릴리스 zip을 전용 S3에 올리고 고정 SSM 문서 하나만 실행한다. StatusCheckFailed 알람이 있다.

배포·State

  • GitHub OIDC 롤 7개, 장기 키 없음. 서버·관리자 API·BackOffice는 대상 Name 태그 한정 ssm:SendCommand, AI는 ECR push + update-function-code만.
  • 이 저장소는 PR에서 tf_plan, main 머지에서 tf_apply가 돈다. bootstrap과 modules/github-actions 변경만 로컬 apply.
  • state는 사전 생성 S3 버킷의 app/·dns/ 키, S3 native lock. DB 비밀번호는 state에 넣지 않고 수동 SecureString이다.

AI 분석 파이프라인 v2

2026-09-08부터 잡 상태·단계 전환·재시도·샤딩은 전부 wes가 소유한다. Lambda가 Lambda를 부르던 자기 재호출·팬아웃·categorize 체인은 삭제됐고, 그에 딸린 InvokeFunction 권한과 lambda 인터페이스 엔드포인트도 뺐다.

GPU score 워커 풀

g6.xlarge 두 대가 AZ마다 한 대씩 public subnet에 있고 생성 직후 정지된다. 켜고 끄는 주체는 세 겹이다.

  • AMI: EC2 Image Builder가 AL2023 x86 위에 NVIDIA 드라이버·Docker·nvidia-container-toolkit·워커 systemd 유닛을 굽는다. 스케줄 없이 수동 실행, 결과 AMI ID를 gpu_ami_id에 박는 PR을 낸다. 서비스 연결 역할 둘(imagebuilder, events)은 코드로 만든다.
  • 코드 이미지: AMI에 굽지 않고 부팅 때 ECR wes-score:gpu(이동 태그)를 pull 한다. 불변 태그 gpu-<sha>는 최근 3개만 남긴다.
  • 워커 롤: previews Get · ECR pull · SSM 파라미터 3개(spring.datasource.url, photoselect.db.password, app.storage.bucket)만 · 자기 풀 태그 한정 StopInstances. 접속은 SSM만, key pair 없음.
  • 스위치: SSM app.analysis.gpu.enabled는 Terraform 소유(gpu_score_enabled, 현재 true). 콘솔에서 바꾸면 다음 apply가 되돌린다.
  • 알려진 드리프트: 정지된 인스턴스는 퍼블릭 IP가 회수돼 associate_public_ip_address가 매 plan마다 replace를 만들었다. #57에서 ignore_changes로 막았다.
